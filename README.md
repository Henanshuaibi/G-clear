# G clear · 0.1

Android 8.0+ 原生广告辅助工具，包名 `cn.g.clear`。不需要服务器、root、VPN 或网络权限。在用户选择的 APP 中点击标准开屏跳过按钮；可按 APP 启用实验性的广告跳转后返回。包含概览、搜索应用与独立开关、今日/累计统计、最近记录、权限及运行指引。

## 权限与可实现边界

- **无障碍服务，必须手动授权**：读取当前可访问界面树并执行点击/返回。Android 用 `BIND_ACCESSIBILITY_SERVICE` 保护服务，普通 APP 不能自行开启。界面在跳转系统设置前说明用途与隐私。本工具并非专为残障用户开发，声明 `isAccessibilityTool=false`。
- **开机广播**：仅记录系统开机/本包更新事件；由 Android 在开机解锁后重新绑定已启用的无障碍服务，不把广播接收误说成服务已运行。不调用普通 `startService()` 启动无障碍服务。
- **可选系统设置**：应用详情、自启动、后台电池策略入口/指引。并不自动修改系统策略；不申请使用情况访问、悬浮窗、通知、忽略电池优化的直接授权、文件权限。
- **系统限制**：强行停止后必须由用户重新打开应用并检查服务；关闭权限、厂商清理、后台限制可能使服务失效，无法承诺永久运行。Android 13+ 侧载安装可能需要在应用详情菜单允许受限制设置。

官方资料：[无障碍服务](https://developer.android.com/guide/topics/ui/accessibility/service)、[受限制设置](https://support.google.com/android/answer/12623953)、[强行停止状态](https://developer.android.com/about/versions/15/behavior-changes-all#stopped-state)、[电池限制](https://developer.android.com/training/monitoring-device-state/doze-standby)。本项目的识别规则与保活设计是基于这些 API 的实现选择，不是系统承诺的广告过滤能力。

### 具体行为

1. 所有 APP 默认关闭，在应用页逐个开启。屏幕锁定时不处理；桌面、系统设置、权限控制器、当前输入法和 G clear 本身不处理。
2. 根据真实活动窗口根节点确定前台包，不直接信任事件来源包名。每次进入新前台 APP 的最初 12 秒内识别；不是只检测操作系统的冷启动，同 APP 内切换页面不重置窗口。
3. 文字/描述匹配“跳过”“跳过广告”“Skip ad”及短倒计时；按钮需在屏幕右上方、小尺寸、可见且可用。只点击可点击的节点或最多两级、小尺寸父节点，不按固定坐标盲点，不使用手势兜底。同次进入最多发送一次成功跳过操作。
4. 每 220ms 最多扫描一次，每次最多 180 个节点、约 18ms 遍历预算，无常驻轮询。节点及时释放，应用列表后台加载，无图标缓存或网页运行时。
5. 跳转防护默认关闭，需另行确认。仅在来源 APP 同时出现符合区域的跳过文字和独立“广告/Ad/Advertisement”标记后，短暂武装 3.5 秒。切换到其他非保护 APP 时，尝试一次系统返回，记录归于来源 APP。经过桌面/设置等保护窗口后解除。无标记的广告跳转不处理。
6. 跳转防护是**跳转后返回**，不能取消另一 APP 已发出的启动请求，也不能保证返回原页面；在此窗口主动打开的正常链接可能被返回。系统/桌面事件若未被及时观察到也会影响判断。可随时关闭某 APP 的跳转防护或全局暂停。
7. 无法保证覆盖图片、视频、Canvas、自绘按钮、未暴露节点的 WebView、摇一摇广告、非右上角按钮、APP 内部广告页面。右上方的普通教程“跳过”也可能被识别，应关闭该 APP 的开屏跳过。不声称去除全部广告素材。

## 安装与试用

```sh
cp ~/G-clear-0.1.apk ~/storage/downloads/
```

使用系统文件管理器安装。打开 G clear →「应用」选择 APP 并开启「开屏跳过」→「概览」阅读说明，前往系统无障碍设置，手动启用「G clear · 广告辅助」。返回检查显示「服务已连接」，从桌面打开选择的 APP 试用。跳转防护建议在基础跳过正常后再逐个启用。广告出现过快或无符合条件的节点时可能无法处理。

「启用防护」是本机暂停开关，不会代替系统权限授权。系统显示启用但还未连接时，会显示等待系统连接；主界面不必常开。建议按手机品牌允许自启动、设置电池不受限制，并在最近任务中锁定应用。重启解锁后再打开概览检查，不把开机广播记录作为服务正常的证据。

### 可选的本机测试 APP

`G-clear-test-0.1.apk` 是独立包 `cn.g.clear.fixture`，只用于可重复的手动测试，无联网权限、无真实广告。

```sh
cp ~/G-clear-test-0.1.apk ~/storage/downloads/
```

1. 安装测试 APP，在 G clear 的应用页为「G clear 测试」开启开屏跳过。回桌面再打开测试 APP，不触摸右上按钮。应自动显示「已收到跳过点击」，对应 APP 计数增加一次。
2. 留在页面，计数不应继续增加。先全局暂停再回桌面重开测试 APP，不应自动点击；恢复防护后再检查。
3. 点击测试 APP 的「切换为误点检查」，回桌面重开。右上「跳过教程」与底部「跳过」都不应被点击，统计不应增加。
4. 测试 APP 的点击回执也可能来自手动触摸，因此必须在不触摸目标按钮时观察。此测试不验证真实广告、跨 APP 返回或开机行为。

## 统计与隐私

SQLite 事务同时写累计、每日和最近事件，串行防止丢失计数。只有 `ACTION_CLICK` / `GLOBAL_ACTION_BACK` 返回成功才记录；**成功表示系统接受操作，不等于广告确实消失**。跳过与返回分别统计，拒绝重复点击，不根据收到的广告事件累加次数。

统计只保存包名、时间、操作类型与计数，不保存页面文字、截图或输入。最近事件保留 200 条，界面显示最近 40 条；每日按记录时手机时区分日，保留约 90 天；累计保留到清空或卸载。改变系统时区不会重算旧日期。应用备份关闭，卸载会丢失数据。清空统计需要再次确认，保留应用防护开关。

## 架构与构建

- `MainActivity`：原生界面、后台加载可启动 APP、搜索和权限引导。
- `ClearService`：系统绑定的无障碍服务、有界树遍历、节点操作。
- `Rules`：纯 Java 文本/区域/时序规则与跳转状态机。
- `Store`：真实 SQLite 统计和有界事件存储。
- `BootReceiver`：记录收到的开机或升级广播，不启动保活循环。

当前 Termux 使用已有 JDK、aapt2、zipalign、apksigner；默认借用 `../pulse-player/tools/` 下的 `android.jar`、`android-res.jar`、`r8.jar`，也可用 `GCLEAR_SDK_DIR` 指定。不依赖此音乐项目的源码或签名。

```sh
cd ~/g-clear
sh build.sh
sh tests/check.sh
sh tests/device-check.sh
sh tests/build-fixture.sh
```

`device-check.sh` 依赖 Android `app_process`，在 Termux 私有目录运行生产 SQLite 代码。不会安装应用或请求无障碍权限。

首次构建已生成独立发行签名。私有文件为 `tools/g-clear.keystore` 与 `tools/signing-password`，本机备份在 `~/.local/share/gclear-signing/`。保留它们才能覆盖升级；**不要上传或公开分享这些文件**。仅公开 `signing-certificate.sha256`。构建会检查签名，缺失/不同则停止，不自动替换密钥。可用 `GCLEAR_KEYSTORE`、`GCLEAR_SIGNING_PASSWORD_FILE` 指定原始备份；复制源码到新环境需要另行提供原签名文件，源码包不含 SDK 与密钥。

已通过：38 项规则、误判边界、去重、时间窗口和来源归属检查；10 项 Android ART 下的真实 SQLite 检查，含 4 线程共 240 次写入、重开恢复、事件保留与原子清空；主 APK 的包名、权限、服务声明、无密钥、签名与 zipalign 检查。独立测试 APK 已编译并验签。
